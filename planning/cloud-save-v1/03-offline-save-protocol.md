# 03｜24 小時離線戰鬥、雲端存檔與一致性

## 保留原機制
最多 24 小時可結算，但超出 24 小時仍只取上限。**離線不需要每分鐘喚醒每位玩家的伺服器計算**，可以在下次登入或領取時延遲運算。

`valid_elapsed = clamp(server_now - session.start_time, 0, 24h)`

已結算的時間、seed 與收益必須使用持久游標扣除；不允許透過登入／登出／換裝置重新拿一次 24h。

## 結算流程
1. 在線時：每個重要動作經過伺服器 API；保存角色版本與資產狀態。
2. 開始離線：服務端鎖定地圖、裝備、寵物、技能優先、藥水、戰鬥條件、ruleset_version、seed 與開始時間。
3. 重新登入：建立該 session 的待結算時間上限，啟動有限預算的模擬；不得信任前端宣稱的離線時長。
4. 若一次模擬超出免費 Worker CPU 時間，分段執行並持久化 cursor；前端可重試，同一進度不重覆計算。
5. 模擬包括技能 CD、屬性與共鳴、擊殺／掉落、背包限制、藥水消耗、死亡／自動復活、試煉連戰停止條件。
6. 全部結算完成後，在同一筆原子交易內更新角色、裝備、物品與寵物、session 狀態及結算帳本。
7. 若計算失敗／斷線，恢復同一 seed + cursor，已提交的獎勵不得再發第二次。

## 防作弊不可妥協
- 伺服器不能接受前端「我在離線期間殺了 N 隻、掉落 SSS 裝」的結果。
- 不使用平均 DPS × 秒數粗估掉落與死亡，除非經過數學證明及大量基準測試可與原規則等價。
- 規則更新不應默默改寫正在結算的 session；按保存的規則版本或經核准的安全遷移政策處理。
- 八格角色和共用倉庫不能因雙設備同步而複製物品。
- 自動存檔頻率與離線開始的確定時點要有明確契約：**以最後服務端確認時間為準**，不因設備本機時間多送獎勵。
- 現有本機戰鬥若僅作為畫面模擬，必須等伺服器回傳權威事件才正式確認收益。

## 測試矩陣
- 時間：0s、59s、1h、12h、24h、25h、48h。
- 同時兩個 claim、兩台設備不同版本、同一 API 重送 10 次。
- 死亡停掛、復活耗時、藥水耗盡、背包滿、自動分解、離線首領、無券連戰失敗停止。
- 不同裝備與共鳴造成不同結果，確保規則未簡化。
- 5、30、100、500 帳號的短時間登入集中結算，記錄 Worker CPU、D1 讀寫、分段次數與 API 失敗率。
- 沒有實際負載測試前，不能承諾 500 人必定全部免費。

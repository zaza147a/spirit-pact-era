# 08｜SQLite 真實資料庫容量實測與約束測試

日期：2026-11-02；本機 SQLite 實測；**非 Cloudflare D1 雲端實測，不代表已部署服務**。

## 資料來源與方法
使用使用者提供的單一 Lv.200 角色 JSON，將資料拆成角色、材料 stack、卡片 stack、寵物及裝備 instance；所有帳號 ID、角色 ID、寵物 ID、裝備 UID 都是全新生成的測試值，沒有複製原玩家 UID。資料庫使用 SQLite、頁面索引、基本 FK、UNIQUE、CHECK，插入後 commit + VACUUM，再測量磁碟檔案大小與 PRAGMA integrity_check。**不含原始使用者 JSON、角色名稱、真實 UID。**

樣本來源內容：背包 61 筆（41 stack、20 件獨立裝備）、人物裝備 10 件、3 隻寵物（寵物裝備 6 件）、卡片 76 種；因此每格角色採 36 件裝備為基準。樣本被重新編成權威資料模型，沒有加入正式遊戲程式邏輯。

## 實測結果
| 場景 | 實際建立角色格 | 實際裝備資料列 | SQLite 磁碟大小 | 每格平均 | 擴成 4,000 格（若非實測則為推估） |
|---|---:|---:|---:|---:|---:|
| 基礎：36 件／格 | **4,000** | **144,000** | **62.97 MiB** | 16,508 bytes | **62.97 MiB（實測）** |
| 100 件／格 | 500 | 50,000 | 12.43 MiB | 26,059 bytes | 99.41 MiB（推估） |
| 300 件／格 | 500 | 150,000 | 26.92 MiB | 56,451 bytes | 215.34 MiB（推估） |
| 500 件／格 | 500 | 250,000 | 41.42 MiB | 86,860 bytes | 331.34 MiB（推估） |

所有四個測試資料庫的 `PRAGMA integrity_check` 都回傳 `ok`。前述非基礎情境將小規模 SQLite 實測結果按每格線性投影到 4,000 格，**不是已建立 4,000 格的大裝備情境**。

## 約束安全測試
在基礎資料庫進行：
- 重複裝備 uid：`PRIMARY KEY` 拒絕。
- 同帳號同角色槽重複插入：`UNIQUE(account_id, slot_index)` 拒絕。
- `item_stacks.quantity<0`：`CHECK(quantity>=0)` 拒絕。
- 裝備指向不存在的角色：**啟用 `PRAGMA foreign_keys=ON` 後** `FOREIGN KEY` 拒絕。

**重要教訓：** SQLite 的 FK enforcement 是依連線設定的；若連線未啟用，單有 schema FK 聲明並不保證拒絕不合法角色 ID。Cloudflare D1 的實際 FK 設定必須以其官方行為及隔離實測驗證；不能直接套用本機 sqlite3 預設。

## 風險與未涵蓋
1. 未將 500 帳號的**真實共用倉庫**、極大量非堆疊材料、歷史戰報、事件帳本實際填滿。
2. 資料庫以 SQLite 本機測試；D1 的儲存統計、實際 rows read/written、CPU、請求額度仍未測。
3. 模擬的 500 件裝備是循環套用同一範例詞條，每件重新產生唯一 UID；不能代表所有組合的實際長度分布。
4. 未模擬 24 小時離線戰鬥的事件推演，也未驗證服務端規則與原版等價。
5. 正式服防作弊需要 **伺服器提交合法操作 + 原子交易 + ownership / nonce / version**，不是只有 UNIQUE/FK 就安全。
6. 本機簡化模型將部分角色設定放在 JSON；實際資料表分割、索引及倉庫策略可能改變容量與效能。

## 下一輪建議
- 建立可重跑的**資料庫遷移 SQL + 隔離測試環境**，將 FK、唯一角色槽、物品非負、裝備位置約束及事件冪等整合為自動測試。
- 實際跑 4,000 格×500 件裝備與獨立共用倉庫負載，驗證 D1 單庫上限與寫入列數。
- 量測真實 24h 離線模擬的事件數、總 CPU 與分段游標，而非只估存檔大小。
- 不上傳任何實際玩家角色 JSON，所有分享數據為匯總統計。

**狀態：本機負載與約束驗證已完成部分，Cloudflare／帳號／雲端驗收仍未實作。**

## 補充：完整極端情境實測（不再只是線性推估）
- **4,000 格角色 × 每格 500 件獨立裝備 = 2,000,000 筆裝備實例**。
- **500 帳號；SQLite 實際資料庫大小：348,930,048 bytes = 332.77 MiB**，包含既定資料表及索引。
- 實際執行約 **21.37 秒**（單機測試環境），`PRAGMA integrity_check = ok`。
- 先前小樣本線性估算 331.34 MiB；完整實測為 332.77 MiB，差約 1.43 MiB。
- 仍未包含真實大量共用倉庫、日誌、備份或 D1 雲端環境；因此**不能以 332.77 MiB 直接聲稱免費 D1 絕對足夠**。

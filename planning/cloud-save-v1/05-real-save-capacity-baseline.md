## 明確設計建議
1. 角色權威核心與歷史戰報分離，避免每次存檔重寫戰鬥歷史。
2. 自動販賣清單可使用 ID 集合／緊湊編碼，不需要每次存檔附帶長陣列（需保留全量可用性與版本相容）。
3. 背包材料用 item_id + qty 記錄；具有隨機詞條的裝備仍需獨立 UID，不能以數量替代。
4. 共用倉庫獨立於八個角色，屬同帳號權威狀態；搬移必須原子化。
5. 進行 P50／P95／最大存檔採樣與真實 D1 資料庫寫入測試，才能確定免費方案容量是否足夠。
6. **避免上傳真實玩家完整存檔到公開 Repo**。報告只能放彙總數字。

## 樣本限制
僅有一份 Lv.200 角色；其自動分解、材料數量及戰報保留量可能不代表其他職業或一般玩家。不能依此保證 500 人八格全滿一定低於 D1 單庫限制。

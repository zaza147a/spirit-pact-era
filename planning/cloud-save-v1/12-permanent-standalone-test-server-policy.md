# 12｜永久隔離政策：單機正式版不修改，新雲端版獨立測試與發布

**決策日期：2026-11-02；使用者明確指定；優先級：最高。**

## 不可違反的正式版保護要求
1. **原本的單機《靈契紀元》永久保留原有功能與程式碼。** 不修改、刪除、清理、重構、改版或重新部署 `main` 與 `dist/`；原本的 GitHub Pages 遊戲網址不變。
2. 所有雲端帳號、資料庫、戰鬥核心、24 小時離線結算、防作弊、UI／登入和測試，都在**獨立開發版本**中製作。
3. **全部驗證通過後也只部署到全新測試伺服器／測試網址**；不可自動合併到 `main`、覆蓋現有 GitHub Pages、替換目前單機版或遷移單機玩家資料。
4. 單機版 localStorage／JSON、共用倉庫及任何既有玩家角色不可寫入、清空或覆蓋。所有測試角色與資料完全隔離。
5. 目前的 `planning/cloud-save-v1` 用於規劃；後續雲端程式可另建專屬 `cloud/*` 開發分支及獨立的雲端部署根目錄。若要更安全，改用**新的 Private GitHub Repository** 作為雲端版主要程式庫；不需變更既有 Repository 公開權限，保留目前單機版站點不受影響。
6. 機密核心模組只能部署到新伺服器，公開前端只有必要介面程式；測試伺服器使用自己的身分提供者配置、Secrets、測試資料庫和網域。
7. CI/CD 僅部署雲端專案的預覽／測試環境，禁止以 `main` 為觸發或輸出目標；明確分開 GitHub Actions workflow、Cloudflare Pages project、Workers service、D1 database。
8. **任何未來讓雲端版影響舊單機版的行動都需要使用者另外明確、具體的新指示**。不能因為「驗收通過」推定使用者授權改動單機版。

## 建議雙專案架構
```text
既有單機版（維持不動）
  原 repo: zaza147a/spirit-pact-era
  main -> GitHub Pages -> 既有遊戲網址
  原本 localStorage / JSON，沒有任何雲端版寫入

新雲端版（完全獨立）
  New Private Repo（建議；尚未建立）
    staging branch -> 新 Cloudflare Pages 測試站
                    -> 新 Workers API
                    -> 新 D1 測試資料庫
                    -> 獨立 Firebase/Auth 設定
  全功能通過 -> **仍只保留在新測試站**，不取代單機版
```

## 驗收時必查
- 比對舊 `main` SHA，雲端版開發過程無 commit、merge、deployment。
- 測試站使用獨立 URL；登入域名及 token audience 獨立。
- 測試 D1 database ID 不等於任何未來正式站。
- 測試伺服器的備份、資料刪除及回復不觸及單機版使用者存檔。
- 雲端版未取得成功驗收前，不公開宣稱已上線；全部通過後仍只標示「雲端測試版」。

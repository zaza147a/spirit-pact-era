# 第十六輪｜四怪持續刷新＋真正首領加入的混戰傷害驗證

**測試分支：** `experiment-weapon-balance-20261102`。正式 `main` 未修改。

## 使用者要求的戰鬥場景
不是把一隻怪固定在場上計算單體DPS，而是原本地圖的正常 `tickEncounters` / `addEncounter` / `combatTick`、四個一般怪物欄位、擊殺補位、首領中途加入、持續多目標技能／普攻／自動補給／怪物反擊／死亡及首領成敗。

**200級：** 界源天穹 191–200 的10種敵人池＋Lv200地圖首領；人物、寵物未強化。
**210級：** 黎明斷層 201／205／209的敵人池＋Lv210黎明裁界者；人物、寵物SSS，曙界契印IV、VIII分組。

## 已實作
- `dist/game.js` 測試專用 `farm()` 把 `singleTarget` 設為false，重置真實地圖遭遇，使用原始 `combatTick()` 自然刷怪，並在第15秒通過原本的 `addEncounter` 邏輯強制一次首領遭遇機率通過。這是**可重播的混戰壓力測試**，不應解讀為自然3.5%的首領遭遇率。
- 直接從測試分支抽取並執行原始 `addEncounter` 函式，先生成四隻普通怪，再呼叫地圖首領，實際取得「**四隻普通怪＋一隻首領＝五名敵人**」，四普通怪槽仍為0、1、2、3，首領槽為null；五個敵人各有不同instanceId。此項是實際原始生成函式的受控依賴單元驗證，**不是完整瀏覽器的90秒實戰**。
- `tests/real-map-boss-summon-source.test.mjs` 將上述生成及事件埋點轉成回歸測試。
- 每次 `dealDamage` 真正扣血新增 `targetInstance`、`targetBoss`：人物／寵物分別計算**普通怪承傷**與**首領實際承傷**，並檢查全部傷害帳恰好相等。
- 戰鬥輸出：總有效DPS、普通怪有效DPS、首領現身後有效DPS、人物與寵物對首領分別DPS、一般怪擊殺、補位、首領出現次數、首領實際擊殺、存活、補給及每分鐘清怪。
- `tests/rank-natural-map-combat.mjs` 將測得的混戰DPS和首領DPS分開排名，不將小怪範圍傷害灌入首領單獨DPS，不以未遭遇首領當成勝利。
- 全部120個職業×融合基本組合；210階契印IV和VIII各測一次，故總共180筆測試場次。
- 獨立分支GitHub Actions的 `farm-smoke`、`farm`、分別保存raw JSON和排名，正式版網站不部署測試代碼。

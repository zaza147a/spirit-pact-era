# 四域極限試煉 — 測試分支交接

分支：`feature/endless-trials-three-bosses`（初期只有三王，後續追加第四王，因此保留舊分支名）。

## 已實作

- 曙光聖港「極限試煉官・亞爾德」入口；Base 200 以上可參與（仍須依一般規則解鎖曙光聖港）。
- ATK／MATK 王：每階 20 秒，攻擊基於初始值每階線性增加 15 個百分點；魔法王明確使用 `matk` 與魔法判定。
- 生存王命中率亦逐階提高（首階命中 250，後續每階 +15），避免高 FLEE 流派始終完全閃避；不套用任何職業專用隱藏修正。
- HP 王：前 30 階 DPS 門檻 `0.5 億 + (階段 - 1) × 0.045 億`，第 30 階 **1.805 億 DPS**；31 階後每階再 +0.5 億 DPS，只有實際命中才計入。
- 清怪王：場上維持 5 隻不主動攻擊的小怪；前 30 階要求 `6 + floor((階段 - 1) / 2)` 隻，每階 HP +2%，第 30 階 **20 隻／30 秒、HP ×1.58**；31 階後每階擊殺目標 +2、HP 再 +10%；即死補怪、無普通收益。
- 每十階解鎖快速起點；首次突破 **1～30 階**才領取極限徽記，31 階以後僅解鎖更多稱號與最高紀錄；四個模式進度獨立。
- **層數沒有遊戲設計上的上限，也不要求高層數一定有人能過關。** 第 30 階後只作為挑戰極限、紀錄和少量稱號，並不設計必然可通關的平衡目標。程式僅受 JavaScript 安全整數表達範圍限制，對目標數值加上溢位保護。
- 為避免高紀錄造成數萬個選單項目卡頓，入場下拉保留第 1／10／20／30 階及最近 20 個十階節點；無論歷史紀錄多高，選單維持固定小尺寸。
- **使用者最新確認：每隻角色獨立挑戰極限，絕不跨角色共用進度、徽記、商店收藏及首次突破獎勵。** 所有資料存在該角色存檔的 `extremeProgress`、`extremeCoins`、`extremePurchases` 等欄位。
- 已加入八件極限商店永久收藏品（四種名稱框、四種背景），個別角色購買；單王通過 30 階可累積 450 徽記，該王名稱框 150、背景 250，**足夠買齊兩件**；名稱框整合既有單選欄，10／50／100 階稱號整合既有稱號選擇欄。
- 五張原創透明 WebP 美術位於 `dist/assets/extreme/`（四王與入場 NPC），遊戲圖像選單及城鎮 NPC 已引用。
- 主要獎勵全部在 30 階前：10 階稱號、20 階名稱框、25 階戰袍視覺特效、30 階背景與光環；**31 階後只有 50／100 階進階稱號與歷史紀錄**。戰袍／光環為 CSS 外觀層（保留原立繪），可在角色外觀頁分開選擇。
- **名稱框視覺升級（本輪）**：八款名稱框現在有實際差異。四種 20 階突破款使用各王專屬色、浮動符印、星光和呼吸光暈；四種商店典藏款另外有皇冠、流動光帶與多層高亮框。不再把典藏框和突破框映射到同一個 CSS 類別。角色欄及登入選角共用設計；支援 `prefers-reduced-motion` 停止動畫。已加入對應單元測試，CSS 查詢版本更新以避開快取。
- `scripts/audit-extreme-trials-12-jobs.mjs` 使用既有 12 職業合法 Lv210 SSS／契印 8 存檔跑四種模式各 20 或 30 秒的戰鬥觀察；並非第 1～100 階完整清關測試。
- 清怪王戰鬥卡片展示萬軍魔主本體立繪、實際 5 名小怪的獨立 HP 與手動選怪按鈕；擊殺後小怪即時補位。
- 挑戰階段完成時恢復人物／出戰夥伴 HP、SP 並重置主要攻擊冷卻；離場／死亡／背景切換結束試煉。
- 不進入正常地圖掉落、經驗或普通野外生怪。
- **2026-11-08 最新規則**：極限試煉可連續線上與離線運行，從任何已解鎖十階起點開始，每階成功立即開下一階；首次失敗／死亡／主動退出才中止。仍不發放普通地圖經驗、金幣或掉落。
- 已新增極限挑戰獨立 checkpoint（敵人五人陣列、HP、敵人攻擊計時、技能冷卻、職業狀態、當前階段時間等），載入與離線 worker 使用同一實際戰鬥引擎，不以預估 DPS 直接發獎。
- 離線最多結算現有系統允許的 24 小時，失敗時提前中止；回到曙光聖港，保留最高階和首次獎勵。若 24 小時內未失敗，保留 checkpoint 供下次繼續。
- 測試：`tests/extreme-trials-offline.test.mjs` 涵蓋離線成功進下一階、失敗停戰保留歷史紀錄、短時間離線資格與頁面切換不直接清除試煉。
- **補充跨登入測試**：第一次離線完成第 1 階後，把整隻角色 JSON 序列化；由另一個全新 VM 模擬重新登入，成功再通過第 2 階進入第 3 階。徽記從 10 增至 20、沒有重領第一階；另一測試驗證清怪模式五隻目標存檔及即時補位，再進下一階。
- **損壞 checkpoint 防護**：匯入的戰鬥快照若缺敵人等關鍵資料，會安全結束本次試煉並回城，不會抹掉此角色之前的最高階紀錄。
- **獨立 Worker 驗收**：`tests/extreme-trials-worker.test.mjs` 在真正獨立的 Node Worker 執行緒載入 `dist/offline-worker.js` 及實際遊戲模組（僅以 `self` shim 銜接執行緒訊息），透過 `postMessage` 傳入存檔；已驗證成功續關回傳角色及傷害不足立即停戰。這比同一 VM 的 API 模擬更接近正式 worker，但**仍非 Chromium／Firefox 的 Web Worker**。
- **八格角色隔離驗收**：`tests/extreme-trials-slots.test.mjs` 直接呼叫遊戲既有 `writeCharacterSlot`／`readCharacterSlot`，A 角色首次突破與購買名稱框後，B 角色存檔原始內容完全不變；這是本地八格角色存取測試，並非 Cloudflare 雲端帳號 API 測試。
- **本輪專項回歸 39／39 通過**：涵蓋極限試煉規則、四王實戰、跨登入 checkpoint、獨立離線 Worker、八格角色隔離，以及既有 `tests/offline.test.mjs`。
- 個別角色進度、商店交易與首次突破記錄都有單元測試；補充角色 JSON 存檔往返及另一角色欄位不被污染的測試。

## 尚需驗收／完成

1. **真實瀏覽器實戰**：12 職業 × 四模式的 48 組引擎觀察與基本 VM 戰鬥測試已跑；但瀏覽器端仍未驗收（本機 Playwright 有套件、缺 Chromium 執行檔，也未發現系統 Chromium／Firefox），需確認互動操作、UI 響應式、雲端存讀檔與實際掛機環境。新增離線 checkpoint 已通過兩次不同 VM + JSON 存檔，以及獨立 Node Worker 的續關測試，但仍需要真實瀏覽器 Web Worker、關頁／回歸與雲端帳號驗收。
2. **角色存檔驗收**：進度與購買紀錄須跟著個別角色匯出／導入及雲端角色存檔，不得讀寫共享帳號帳本。

4. **數值校準**：ATK／MATK 第一階目前以曙界首領攻擊力的 20% 為暫定基礎，需以合法 200／210 等十二職業裝備實際測試調整；清怪 HP 同樣暫用曙界怪物基準。

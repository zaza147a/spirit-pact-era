# 正式傷害驗證改為實際 combatTick 引擎（2026-11-02）

## 使用者驗收要求
禁止再以攻擊詞條×攻速、技能倍率／冷卻等理論代理模型充當最終 DPS。必須逐次執行遊戲原本 `dist/game.js` 的 `combatTick`，包含：
- 人物主動技能、自動排序／冷卻／吟唱、暴擊／命中、寵物技能、共鳴、首領反擊；
- 真正對怪物造成的有效扣血、角色與夥伴傷害歸屬、擊殺時間、死亡狀態；
- Lv200無強化的191～200地圖及首領，Lv210全SSS的201～210地圖及首領；
- 各等級10職×6無序融合，全部120組，武器與配點必須合法。

1. `dist/game.js` 僅在 `?lingqi_combat_test` 查詢參數啟用測試專用 `globalThis.__lingqiCombatHarness`。可重設人物、武器、屬性、寵物、強化及契印階段，執行**真的** `combatTick`，逐筆收集 `dealDamage` 有效命中傷害。
2. `tests/real-combat-browser-benchmark.mjs` 新增 Playwright/Chromium 瀏覽器腳本，對照少量煙霧測試或完整職業×融合配置，重複呼叫遊戲戰鬥回圈；採固定偽隨機種子，輸出 `ownerDamage`、`petAttributedDamage`、`kill`、`dead`、`elapsedMs`、`hits` 等。
3. `.github/workflows/isolated-weapon-fusion-ci.yml` 中新增獨立瀏覽器煙霧測試 job。
4. `.github/workflows/actual-combat-120.yml` 啟用獨立分支 GitHub Actions：先煙霧測試，再跑全量真實戰鬥測試，保留原始JSON報告；不部署正式版。

## 2. 確認過的職業設計
- 第 11 職一轉 **御靈使**（程式 ID `spiritist`），**一轉即能帶兩隻夥伴**；其他十職業始終只有一隻。
- 二轉 A **靈契戰使**（`pactWarrior`）：人物主攻；每隻夥伴獨立切換「協戰／同化」；同化時夥伴停止獨立攻擊，部分能力轉化給人物。進階二轉 **靈契戰將**；三轉 **靈契君王**。
- 二轉 B **雙靈指揮官**（`spiritCommander`）：夥伴主攻；進階二轉 **雙靈統御者**；三轉 **萬靈宗師**。
- 一、二、進階二轉維持精簡，**前期只需以非融合寵設計**。三轉重心才是兩隻融合寵，提前拿到融合寵仍可出戰、但不能提前開三轉共鳴。
- 程式中第二夥伴傷害因路線不同：御靈使 50%；指揮官 70%；指揮官三轉短暫超載可 100%（初始設計 10 秒／60 秒 CD）；戰使協戰第一寵 50%、第二寵 35%，同化時該寵不直接輸出。**這些是開發參數，不是已完成所有職業平衡的實測定案**。
- 需完成兩隻夥伴的養成與兩套夥伴裝備；成長期間可以略弱於原十職，但正常地圖不可卡關；**完全養成後希望擅長項目進前三**：靈契君王偏單體／首領前三、清怪前五；萬靈宗師偏群怪前三、首領前五。不必兩條路線所有項目都第一。必須用實際戰鬥而非靜態倍率驗證。
- 兩隻融合寵必須**同時配置**且完成 **「雙生靈契」** 支線才能三轉，原有 Base／轉生二轉 Job／主城／聖印門檻仍需同時遵守。支線：Base 140、轉生後在蒼穹樞城接取，兩隻出戰融合寵共同存活擊敗 24 隻 101–150 級敵人，返回主城完成誓約。**早期即在左側 UI 提醒**，不可等到 140 才首次告知。三轉後暫卸一隻融合寵不退轉，但雙融合專屬效果停用。
- 四種基本寵：攻擊／魔法／防禦／輔助；六個**無序**融合類型、允許同一融合類型的兩個不同寵物個體同時配置，兩寵配對共 21 組；兩二轉路線各 21 組 = **42 組雙靈三轉特效**。原本的正向／逆向融合僅外觀或名稱不同，能力相同，不能重複計數。
- 專屬裝備掉落**種類**比例：一般十職「人物 90%：寵物 10%」；御靈使一／二轉 **80:20**；進階二轉／三轉 **70:30**。只在「原本已判定掉裝」後分流種類；**不可提高總裝備掉率、稀有度或件數，也不影響卡片／金幣**。
- 雙寵各自 HP／SP／CD／裝備／死亡復活；夥伴裝備頁能選第一或第二夥伴並比較裝備，避免誤穿錯夥伴。

## 3. UI 方向與特殊限制
- **只對御靈使職系**擴大左側欄位；其他十職維持原 UI。
- 左側目標：上方人物、下方兩隻夥伴，各自立繪及 HP／SP；優先在一般桌面高度下**不必垂直捲動**。人物旁留空位顯示雙靈成長／融合／支線進度，能點擊看到下一步。
- 不修改所有職業 UI 來遷就御靈使；需驗證窄螢幕／縮放時不遮擋戰鬥。
- 遊戲規則與原職業一致：角色／夥伴／裝備成長、卡片、存檔、武器、技能優先順序、無序融合、同樣的 ASDP、暴擊與傷害公式。
- **戰術系統完全排除在職業平衡比較目標之外**：模擬需清除 `player.tacticEffect`，但一般職業技能、寵技、被動、三轉共鳴照常算；不可把「戰術」和「職業技能」混淆。

- 契印／刻印 **0**、減傷上限 **40%**、合法總素質點與卡片詞條、LUK、穿防、攻速、暴擊機率的期望傷害全部納入。**不能預設全部職業 100% 暴擊**。

## 6. 最近完成：長時間離線結算效能優化
離線 Worker 使用 `dist/game.js` 戰鬥模擬，時間格 **100ms**，最長 **24 小時**，也就是最壞情況約 864,000 格。已針對不更動掉落／戰鬥結果的熱點改善：
1. 完全空閒時跳過沒有事件的空白 Tick，但不能越過怪物刷新、回復或自動補給時點。
2. Worker 的進度回報改按真實牆鐘時間適時 yield，降低過密回報造成的額外成本。
3. 滿怪時跳過重建怪物陣列／欄位刷新掃描：局部 20 萬次測試約 633ms→594ms（~6%）。
4. 寵物技能 850ms CD 未完成前，避免每 100ms 預先跑 `petStats`；60 秒測試同樣 66 次技能觸發，這條路徑的能力值計算 600→66 次（~89% 減少呼叫，**不是整體加速 89%**）。
5. `dist/adventure-economy.js` 自動販售：沒勾選則立即返回，同輪出售只計算一次需保留的任務雜物。500 物品／5,000 次合成測試 1367ms→1071ms（約 21.7% **局部函式**改善）。
6. 一般掉落只篩選一次可掉落候選，寵物裝備類型清單重用，避免額外的物件分配；隨機 RNG 次數不改變。
7. 怪物補刷的 `WORLD_MONSTERS` 依地圖的候選清單快取，不再每次刷新重新篩整張怪物表。
8. 已將補怪時序、掉落候選／RNG、任務雜物、寵物技能冷卻等檢查加入 `tests/offline-optimizer-regression.mjs`。
